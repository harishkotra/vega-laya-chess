# Play

The Play tab is the demo: a real game of chess, a local decision model on each
side, and every choice each one makes printed on the board as it happens. Vega
0.8B against Laya 421M is the default match.

## What is actually being demonstrated

Neither model searches. Each reads the position, scores the moves it is offered
and returns one, in a single forward pass. Neither can see that a quiet move sets
up something three moves later, because nothing in the pipeline looks three moves
ahead.

So the game is not a strength claim and the result is not the point. The
interesting output is:

- **which move it picks**, out of the set it was offered,
- **how sure it was**, as a calibrated probability on each option,
- **whether it flagged itself as unsure**, through the abstain field,
- **what the conformal set contained** at the configured risk,
- **how long it took**, one forward pass per move.

A model that hangs a piece with 0.31 confidence is telling you something. A model
that plays the only move that saves the position with 0.05 confidence is telling
you something else. Both are visible here, per ply.

And with two models, the comparison is per position: the same board, the same
capped option set, two distributions. Where they disagree is the content.

## The rules of the game

**The model never plays an illegal move.** It can only choose from the options it
is handed, and the options are legal moves generated by the app's own rules
engine. Everything it gets wrong, it gets wrong inside the rules.

**The option set is capped, and the cap is per model.** A position can have forty
legal moves, and the choice question gets harder than the game as the list grows,
so the set is capped (8, 12, 20 or 40 in the UI, 20 by default). The fill rule is
stated rather than hidden: every capture, check, promotion and castle is kept
first, then quiet moves are added at random until the cap is reached. The ply
record says how many legal moves there were, so a capped decision is never
presented as a free choice among everything.

The cap is also clamped to what the model can read. Vega's window is 73,728
tokens, so 40 options fit. Laya's is 1,024 tokens with 256 reserved for the
question and its options, so a Laya choice question is capped at 20 and the app
will not offer more. The player's summary and the ply record both carry the cap
that was actually used.

**Both players are named in the record.** A ply says which model moved, by key
and by name, or `random` when a side is playing random legal moves.

**Nothing is scored.** The benchmark scores every answer against a verified
answer. A game has no verified answers, so it reports choices, probabilities and
the result, and nothing else. Do not quote a game as evidence about accuracy: use
the Benchmark tab for that.

## The opponents

| side | what it is | when to use it |
| --- | --- | --- |
| **Vega 0.8B** | the public intents checkpoint, run by `vegaml` | the larger model, with its own abstain flag and conformal sets |
| **Laya 421M** | Convai Innovations' multilingual checkpoint, run by `laya` | the smaller, faster model, for the comparison |
| random legal moves | a uniform random legal move | a baseline. A model should beat this, and if it does not, that is a finding |

Every side is local. There is no chat model, no endpoint and no key: the app
cannot send a position anywhere, because the only thing it can talk to is a model
on this machine.

**A model only ever plays a legal move**, because it can only choose from the
options it is handed, and the options come from the app's own rules engine. When
it does not choose one of the offered moves, the ply records the answer it gave
and the game ends with that reason, rather than guessing at what it meant.

## Reading a ply

The detail panel under the board shows, for every ply:

- which model moved, by key and name
- the options offered, and how many legal moves existed
- its probability on every option it was offered, as bars
- the option it chose, and its confidence in it
- whether it abstained, and where that flag came from
- the conformal set, for the model that produces one
- the mate questions, if you turned them on
- the exact state text it read

Two things differ between the models and both are stated in the panel rather than
smoothed over. The app records **the top probability** as the confidence for both,
so the calibration curve compares like with like, and keeps Laya's own numbers
(`confidence`, which is how concentrated the distribution is, and
`answer_confidence`, the calibrated one) under their real names. And Laya has no
abstain flag of its own, so the app applies a confidence floor of 0.5 to the top
probability and says so: the ply reads "top probability below 0.5 (this model has
no abstain flag)".

## The mate questions

By default the game asks one question per move: which move to play. The
checkbox adds the two mate questions, which is the read-once showcase (three
questions, one read of the state) and also a leak test: the boolean and score
questions name mate, so turning them on may help the move question. If you want
to compare, run the same start position with them on and off. That is the same
distinction the benchmark calls isolated against combined.

## Watching a finished game

The Games tab keeps every game on disk. Pick one and step through it ply by ply
with the slider or the buttons: the board shows the position after that ply with
an arrow for the move, the move list highlights where you are, and the detail
panel shows exactly what the player on that side was thinking, or what it
replied.

Games live in `<data dir>/games/`, one append-only `.jsonl` per game plus a
`.json` when it ends, so a game that dies halfway keeps every ply it played. The
game's config records which model played each side, the option cap, the seed and
the start position, so any game can be described exactly and replayed.

## How to run one

1. **Setup**: download and load the models you want, once each.
2. **Play**: choose which model plays each colour, press *Start the game*.
3. Watch. A game of about sixty plies takes a few minutes: Vega is the slower of
   the two, Laya answers a question in tens of milliseconds.

The models, the option cap, the seed and the start position are all recorded in
the game file, so a game can be described exactly and replayed.

## Limits, stated plainly

- Neither model has any lookahead. Both judge the position in front of them.
- The in-game option cap means a model sometimes cannot play a move that a full
  search would call best, because the move was not offered. The record says so,
  and the cap is per model.
- A game is not a benchmark: no ground truth, no accuracy, no calibration figure.
  Two models playing each other is a demonstration, not a measurement. The
  Benchmark tab is where the measurement lives, and it can run either model on
  the same verified positions.
- Laya ships over-confident on its own data, so its probabilities are worth
  reading against the benchmark run rather than in isolation.
